# MAP 与房间设计勘探 · 2026-11-16

本文为勘探结论与待选方案，不替代 `lore/world.md` 的正式设定；未修改游戏原型。

> 后续（2026-11-17）：其后形成的空间方案 A-01 见 `design-studio/`；原型地图已改用该模型，`lore/world.md` 的 `facility` 一节已按它同步。下文描述的是当时的状态，保留作为依据。

## 当前已经有什么

- 设定：长方形四区，Lutie 区 25㎡、观察办公区 15㎡、水族研究区 20㎡、南侧共享生活区 40㎡。
- 原型：`prototype/js/map.js` 用米制坐标定义 12.5×8m 的设施，绘制玻璃隔断、门洞、池、坡、家具、设备和固定观察位；支持生态、湿度、以太三种显示。
- 主要尺寸：西北区 5.2×4.8m，中北区 3.125×4.8m，东北区 4.175×4.8m，南侧 12.5×3.2m。实际分区几何面积为 24.96、15、20.04、40㎡，界面四舍五入为设定面积；这些面积未扣墙体，不能直接当作室内净使用面积。
- 主池轮廓外接矩形 4.8×4.25m，圆角半径 0.8m；以圆弧解析式近似，水面约 19.85㎡。南侧浅水平台外接矩形 2.75×1.75m、圆角 0.4m，约 4.68㎡。实际代码将圆角离散成折线，面积会有小幅差别。
- 东北区已有 3.4×0.8m 长缸、侧缸、直径约 0.9m 的水体培育柱、操作台、蒸汽环境设备和管线，不是只有桌面小鱼缸。
- 观察画面使用独立背景图与角色图叠加。背景呈现弧形水体、上部环廊、台阶和岩洞；并非由 MAP 几何投影而来，尚未建立建筑、镜头、美术的一一对应。

## 对四条意见的衡量

### 1. 垂向标高缺失：成立，优先级最高

现有设定没有统一的人类地坪、水面、深池底、浅台底、观察室地坪、摄像机眼高。MAP 主要把水面与家具基面绘在同一参考平面，局部坡仅定义 0.35m 下探。墙体 0.75/1.3/1.7m 是全息展示裁切高度，不能作为真实建筑层高。

缺标高并不意味着方案必然无法成立，而是目前无法证明主视角与通行同时成立。只加“深挖 2m”仍不够：水面若低于人类地板，同层坐着或站着仍主要俯视水面；眼睛必须低于水面，才能确定平视水下的取景。

建议优先验算“下沉池体＋局部下沉观察位”，保留人类生活与亲水平台靠近上层地坪。一个仅用于验证剖面的假设为：上层地坪 ±0.00m、水面 −0.15m、池底 −2.20m、观察位地坪 −1.80m、坐姿眼高距该地坪 1.15m，得到眼位 −0.65m，低于水面 0.50m。这些数值不是正式设定，也不足以保证现有背景图原样成立。

后续必须把观察位的楼梯、平台、净高及设备观察关系画进去。15㎡ 若同时承担错层通行、办公和观察，不能继续按原家具配置直接套用。高架池也是可行候选，但会抬高亲水平台，改变生活区的进出关系与整体层高。

露缇能游泳，不必从 2m 深池底沿一条干坡一路爬出。更适合“深水→水下浅台→短坡→湿平台”；水下坡与浅台要计入池的投影面积，不能把 20㎡ 全部写成纯深水区。若假设用现有坡度 1:3、宽 1.6m 克服完整 2m 高差，水平长约 6m、占地约 9.6㎡，只是几何演算，不是推荐坡度。

### 2. 南侧过载和干湿混杂：边界问题成立，面积判断需修正

40㎡ 对单人厨房、卧室、客厅并非天然不足。问题是当前南侧仅深 3.2m，另塞入浅池、加湿客厅、入口和通行，卧室只用局部屏风分隔，没有画出可信的干湿气候边界。

将亲水活动集中到 Lutie 区是合理方向，但不能直接认定“25−20=5㎡ 正好够”。现有约 5.1㎡ 余量散布在池周，部分直边余量只有约 0.2m；重新集中成宽 5.2m 的前缘带，5㎡ 对应深度约 0.96m，尚未扣墙、家具和人的站位。当前南侧浅水平台本身已约 4.68㎡，把它搬进西北区，会挤压池体或要求重排形状。

可以先试“约 20㎡ 水域（含深水、浅台和水下坡）＋约 5㎡ 紧凑湿平台”，研究员主要站在相邻干侧互动；若希望两人围桌停留或保留小客厅体验，则应给亲水空间更多面积，或保留南侧一个封闭湿润凹间，重新分配名义面积。

矮防水堰只能挡液态水，不能隔湿。湿区与干区需要有实际可关闭的玻璃隔断、通风/除湿服务边界；门槛还要兼顾露缇的通行，不能为了挡水破坏连续短坡。

### 3. 东北区与玩法脱节：值得重构，现状描述不完全准确

其已有专业水族设施、取样和环境控制设定，因此不宜称为“纯凑面积”。两侧水体也没有必要体量对等，观察室的价值来自观察对象与工作流程，而非对称。

建议强化为“以太维生与样本培育区”：主池循环过滤与温控、以太供能与调光、幼体/样本培育、清洗检修共同获得空间位置。主界面的操作就能对应到具体设备及其作用对象。

“生态联动”不等于所有样本缸与主池直接混水。可以共用能源、控制和换热，保留可隔离的水路；空气调湿应对应各空间的风路/除湿设备，不能仅用水质过滤器解释。观察室如果下沉，右侧设备和培育柱也要在剖面中重新检查可视高度。

原型目前只让 `light` 影响以太动画速度；温度/湿度由 HUD 定时随机小幅漂移，地图湿度来自固定源的高斯叠加，并不读取同一湿度状态，也没有门开合、风路或设备状态。因此当前热力线是视觉示意，不能作为隔湿方案的验证。

### 4. 离水限制与人类生活冲突：不属于硬矛盾，三段梯度值得保留

人设明确允许短时处于常湿空气：约 6 小时后不适、8 小时左右危及生命；湿润空气可延长这一过程 2–4 倍。模仿使用桌椅餐具与这一限制可以共存。数值描述的是生理风险区间，不应当作推荐日常离水时长，也不能未经定义直接套到更干燥区域。

建议采用“深水恢复/休息→湿润日常互动→受控短时访问干区”。把投喂、陪伴和主要交互集中到湿平台与观察窗，同时保留她偶尔接近研究员生活区的可能性。全面禁止进入会删去原设定中主动模仿和跨物种共居的内容，并非修复空间逻辑的必要条件。

还需明确：脚下浅水、体表补水、高湿空气和全身浸水分别怎样影响水分状态；记录离水时间或水分变化，并提供主动回水、补水和观察提示。无需在此阶段编造具体消耗速率。

## 另外发现的设计缺口

1. 总平面、剖面和主背景尚无统一几何来源。尤其背景的弧形环廊与矩形四区，应明确是局部造型、艺术夸张，还是另一版设施。
2. 门在代码中是固定打开的绘图对象，没有房间通行状态或房间切换；`HER` 与 `YOU` 是固定位置，尚无空间行为模型。
3. 隐蔽休息区有静态石堆意象，但没有“不可主动观察”状态；未来感官/地图显示需区分角色真实位置、可观测位置和隐私状态。
4. 若 100㎡ 被定义为完整的长期居住设施，还需容纳卫生、清洗、储物、设备检修和错层交通；若只是研究所内的一个模块，应在图上注明外接公共设施，避免隐形扩建。
5. MAP 的分区与家具坐标、湿度源、角色位置都集中硬编码在绘图文件里。后续宜先抽出统一空间数据（地坪/水位/池底/墙/门/设备/镜头/连接），让平面、剖面与全息渲染读取同一套定义。
6. 次要交互问题：全局 `pointerdown` 只排除 `.w`，未排除 MAP 模式。在浏览器查看地图视图切换时观察到敲玻璃台词反馈；应避免地图操作触发照料场景互动。
